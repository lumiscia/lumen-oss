# 3D

Lumen draws 3D scenes with the nodes of the `scene` category and `render_3d`, which turns a scene into an ordinary raster. Use them for objects seen by a real camera, glTF models, extruded text and outlines, lathed profiles, and 2D layers placed in depth.

The [node reference](node-reference.md) lists every param. [`examples/README.md`](../examples/README.md) has three compositions you can render.

Each example below is the composition as JSON, then the TypeScript that builds it. The JSON shows `nodes` and `connections`; add `timeline` and `render_settings` as in any composition. Media names such as `fox.glb` stand for files you provide.

## Scene and raster ports

Every node input and output has a kind: `raster`, `scene` or `material`.

- A raster is an image: what `text`, `shape`, `media_in` and every other 2D node produces.
- A scene is objects, lights and cameras. `shape_3d`, `text_3d`, `extrude_3d`, `lathe_3d`, `image_plane_3d`, `model_3d`, `light_3d`, `camera_3d`, `merge_3d`, `instance_3d` and `particles_3d` output scenes.
- `material_3d` outputs a material, which only the `material` input of `shape_3d`, `text_3d`, `extrude_3d`, `lathe_3d` and `image_plane_3d` takes. See [materials](#materials).

An input takes only its own kind. Wiring a scene into a raster input, a raster into a scene input, or a material anywhere but a `material` input fails `check` with `connection.wrong_kind`.

`render_3d` is where a scene becomes a raster. It draws the scene on its `scene` input over a transparent background, so its output composites like any other layer. (`environment_background` shows the environment map behind the scene instead.) Going the other way, `image_plane_3d` and the `texture` inputs of `material_3d` and `model_3d` take a raster into a scene.

`render_3d` draws one scene. To draw several objects, a light and a camera together, wire them all into one `merge_3d`, whose `objects` input takes any number of scenes. A camera and lights are scene nodes like any other.

```json
{
  "nodes": [
    { "id": 0, "type": "material_3d", "params": { "color": "#e6b45a" } },
    { "id": 1, "type": "shape_3d", "params": { "rotation": [20, 35, 0] } },
    { "id": 2, "type": "camera_3d", "params": { "position": [0, 1.5, 4], "look_at": true } },
    { "id": 3, "type": "merge_3d" },
    { "id": 4, "type": "render_3d" },
    { "id": 5, "type": "media_output" }
  ],
  "connections": [
    { "from_node": 0, "to_node": 1, "to_port": "material" },
    { "from_node": 1, "to_node": 3, "to_port": "objects" },
    { "from_node": 2, "to_node": 3, "to_port": "objects" },
    { "from_node": 3, "to_node": 4, "to_port": "scene" },
    { "from_node": 4, "to_node": 5, "to_port": "source" }
  ]
}
```

```ts
import { Composition, nodes as n } from "@lumiscia/lumen-sdk";

const composition = new Composition({ timeline: { durationSeconds: 3 } }).addOutput(
  n.render_3d({
    scene: n.merge_3d({
      objects: [
        n.shape_3d({
          rotation: [20, 35, 0],
          material: n.material_3d({ color: "#e6b45a" }),
        }),
        n.camera_3d({ position: [0, 1.5, 4], look_at: true }),
      ],
    }),
  }),
);
```

## Units, axes and transforms

World units are metres. X points right, Y points up, and a camera looks down its own −Z, so +Z points toward the viewer.

`position`, `rotation` and `scale` are `[x, y, z]` values, so one expression can drive all three axes with `vec3(x, y, z)`.

- `rotation` is in degrees. It turns about Y first (yaw), then about the turned X (pitch), then about the turned Z (roll).
- `scale` multiplies along the object's own axes. A node applies its scale first, then its rotation, then its position.
- A child's transform is in its parent's space. `merge_3d` has `position`, `rotation` and `scale` of its own and places everything wired into it together, so nested merges build a hierarchy.

This group turns about Y, and its two shapes turn with it:

```json
{
  "nodes": [
    { "id": 0, "type": "shape_3d", "params": { "position": [1.2, 0, 0], "size": [0.8, 0.8, 0.8] } },
    {
      "id": 1,
      "type": "shape_3d",
      "params": { "shape": "sphere", "position": [-1.2, 0, 0], "size": [0.8, 0.8, 0.8] }
    },
    { "id": 2, "type": "merge_3d", "params": { "rotation": "=vec3(0, (time * 45), 0)" } },
    { "id": 3, "type": "camera_3d", "params": { "position": [0, 2, 5], "look_at": true } },
    { "id": 4, "type": "merge_3d" },
    { "id": 5, "type": "render_3d" },
    { "id": 6, "type": "media_output" }
  ],
  "connections": [
    { "from_node": 0, "to_node": 2, "to_port": "objects" },
    { "from_node": 1, "to_node": 2, "to_port": "objects" },
    { "from_node": 2, "to_node": 4, "to_port": "objects" },
    { "from_node": 3, "to_node": 4, "to_port": "objects" },
    { "from_node": 4, "to_node": 5, "to_port": "scene" },
    { "from_node": 5, "to_node": 6, "to_port": "source" }
  ]
}
```

```ts
import { Composition, nodes as n, time, vec3 } from "@lumiscia/lumen-sdk";

const composition = new Composition({ timeline: { durationSeconds: 4 } }).addOutput(
  n.render_3d({
    scene: n.merge_3d({
      objects: [
        n.merge_3d({
          rotation: vec3(0, time.mul(45), 0),
          objects: [
            n.shape_3d({ position: [1.2, 0, 0], size: [0.8, 0.8, 0.8] }),
            n.shape_3d({ shape: "sphere", position: [-1.2, 0, 0], size: [0.8, 0.8, 0.8] }),
          ],
        }),
        n.camera_3d({ position: [0, 2, 5], look_at: true }),
      ],
    }),
  }),
);
```

## Cameras

`camera_3d` is the viewpoint `render_3d` draws from.

- `projection` is `perspective` (the default) or `orthographic`. A perspective camera has a vertical `fov` in degrees, 40 by default. An orthographic one shows a view `ortho_height` world units tall, and things keep their size at any distance.
- The view's width follows the aspect ratio of `render_3d`'s output.
- `near` and `far` bound what is drawn, 0.05 and 1000 by default.
- `position` is 5 units along +Z by default. Aim the camera with `rotation`, or turn on `look_at` to aim it at `target`, which then ignores `rotation`. With `look_at`, the camera's up direction is +Y, or Z when it aims almost straight up or down.
- The first camera in a scene is the one used, in the order the objects are wired. A scene with no camera is seen from `[0, 0, 5]` with a 40° field of view.
- A glTF model's own camera counts as a `camera_3d` placed at the model. See [model_3d](#model_3d).

A `wgsl_shader` with a scene on its `camera` input reads that scene's camera, chosen the same way, as `lumen.view` (world to view), `lumen.projection` (view to clip, for the shader's output aspect ratio) and `lumen.camera_position` (world space). A shader that draws something lined up with a 3D scene, such as a sky or a glow around an object, takes the same scene `render_3d` does. Without a `camera` the matrices are the identity and the position is zero. This needs the `3d` feature, like every scene input.

```wgsl
let clip = lumen.projection * lumen.view * vec4<f32>(0.0, 0.0, 0.0, 1.0);
let origin_ndc = clip.xy / clip.w; // where the world origin lands, in -1..1
```

An orbiting camera uses an expression for `position`:

```json
{
  "nodes": [
    {
      "id": 0,
      "type": "material_3d",
      "params": { "color": "#4aa3ff", "metallic": 1, "roughness": 0.3 }
    },
    { "id": 1, "type": "shape_3d", "params": { "shape": "torus" } },
    {
      "id": 2,
      "type": "camera_3d",
      "params": { "position": "=vec3((sin(time) * 4), 1.5, (cos(time) * 4))", "look_at": true }
    },
    { "id": 3, "type": "merge_3d" },
    { "id": 4, "type": "render_3d", "params": { "tone_mapping": "agx" } },
    { "id": 5, "type": "media_output" }
  ],
  "connections": [
    { "from_node": 0, "to_node": 1, "to_port": "material" },
    { "from_node": 1, "to_node": 3, "to_port": "objects" },
    { "from_node": 2, "to_node": 3, "to_port": "objects" },
    { "from_node": 3, "to_node": 4, "to_port": "scene" },
    { "from_node": 4, "to_node": 5, "to_port": "source" }
  ]
}
```

```ts
import { Composition, cos, nodes as n, sin, time, vec3 } from "@lumiscia/lumen-sdk";

const composition = new Composition({ timeline: { durationSeconds: 6 } }).addOutput(
  n.render_3d({
    scene: n.merge_3d({
      objects: [
        n.shape_3d({
          shape: "torus",
          material: n.material_3d({ color: "#4aa3ff", metallic: 1, roughness: 0.3 }),
        }),
        n.camera_3d({
          position: vec3(sin(time).mul(4), 1.5, cos(time).mul(4)),
          look_at: true,
        }),
      ],
    }),
    tone_mapping: "agx",
  }),
);
```

## Lights

`light_3d` has four kinds:

| `light`       | Shines                                                                                                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `directional` | In parallel along the light's −Z, like the sun. Its `position` has no effect.                                                                                                |
| `point`       | Every way from its `position`. `range` is the distance past which it has no effect, as for a spot light; 0 is unlimited.                                                     |
| `spot`        | In a cone along the light's −Z from its `position`. `spot_angle` is the cone's full angle in degrees, and `spot_softness` the fraction of it, from the edge, that fades out. |
| `ambient`     | Evenly on every surface from all around. Its `position` and `rotation` have no effect.                                                                                       |

`color` and `intensity` set the light. `intensity` is a unitless multiplier, 3 by default, and point and spot lights fall off with the square of the distance. The default `rotation` of every light is `[-45, 30, 0]`, which points a directional or spot light 45° down.

A scene with no lights gets a default key light and an ambient fill. A scene lit by an [environment map](#environment-maps) and no lights gets none.

`render_3d` also lights every surface from all around with an environment, a built-in studio unless you set `environment_map`. It gives metals something to reflect. Its `environment` param is the brightness of that light, and 0 turns it off.

### Shadows

Turn on `cast_shadows` on a directional, spot or point light, and objects between it and others block its light.

- `shadow_softness` is how wide shadow edges blur, in world units. It is 0.02 by default.
- A directional light's shadows cover what the camera sees out to `shadow_distance`, 50 by default, measured from the camera along its view. A larger distance trades sharpness for reach.
- A spot light's shadows cover its cone, up to 170° across.
- A `render_3d` draws shadows for the first 8 lights casting them, in the order its scene inputs are wired. The rest light the scene without shadows, with a `scene.shadow_limit` warning.

A `material_3d` takes `cast_shadows` and `receive_shadows`, both on by default, for the `shape_3d`, `text_3d`, `extrude_3d`, `lathe_3d` and `image_plane_3d` it is wired into, and `model_3d` takes them itself. Unlit and glowing surfaces cast shadows too, so a shape that stands in for a light, such as a bulb around a point light, needs `cast_shadows` off.

An unlit surface shows no shadows unless its `material_3d` sets `unlit_shadows`, from 0 to 1. Its base colour is then multiplied by `1 - unlit_shadows × shadow`, where `shadow` is the fraction of the light reaching that point that shadows take away, measured as a shadow catcher measures it, so at 1 a fully shadowed point is black. With several lights, each counts by how much light it brings to the point, so a near light's shadow is darker than a far one's. The colour itself stays unshaded, and `receive_shadows` off turns it off. That keeps a flat or pixel-art look at its exact colours while objects still shade each other, as a `material_3d` with `"unlit": true, "unlit_shadows": 0.45` does.

`shadow_catcher` on a `material_3d` shows nothing but the shadows falling on it. It darkens what the render is composited over by the light the shadows take away. That puts a shadow under an object on 2D footage:

```json

    { "id": 3, "type": "material_3d", "params": { "shadow_catcher": true } },
```

```ts
          n.camera_3d({ position: [0, 1.6, 4.2], look_at: true, target: [0, 0.4, 0] }),
        ],
      }),
    }),
  }),
);
```

## Materials

`material_3d` sets how a surface responds to light. Wire it into the `material` input of a `shape_3d`, `text_3d`, `extrude_3d`, `lathe_3d` or `image_plane_3d`. One `material_3d` can feed any number of objects, which then share its params, so changing it changes them all. Each param takes an expression, as on any node.

- `color` is the base colour. It must be a solid colour, not a gradient. It multiplies the `texture` on a shape and the raster on an image plane.
- `metallic` is 0 for a dielectric such as plastic and 1 for a bare metal. `roughness` is 0 for a mirror finish and 1 for fully diffuse. Both run from 0 to 1.
- `emissive` is light the surface gives off, as a multiple of its base colour.
- `opacity` multiplies the alpha. With `alpha_mode` `blend`, anything below 1 is drawn blended.
- `alpha_mode` is `blend`, the default, or `mask`, and `alpha_cutoff` is the alpha a texel needs to show under `mask`. See [cut-out cards](#cut-out-cards).
- `unlit` shows the base colour as it is, ignoring lights.
- `double_sided` draws the back of each face too. It is off by default, so a single-sided face is invisible from behind.
- `cast_shadows`, `receive_shadows`, `unlit_shadows` and `shadow_catcher` are covered under [shadows](#shadows).
- `texture` is an optional raster input that a `shape_3d` shows, multiplied by `color`, through the texture coordinates described under [shape_3d](#shape_3d). The surface stays lit, fogged and shadowed, and sorts in depth with the rest of the scene. The texture's alpha counts only where the material is blended, through `opacity` or the colour's alpha. Wired into a `text_3d`, `extrude_3d` or `lathe_3d`, a material with a texture fails the render, naming the object, unless it has a `projector`. An `image_plane_3d` shows its own source, so a material with a texture fails on it either way.
- `sampling` is how the texture is read, as on `image_plane_3d`: `linear` filters it, with mipmaps when it is shown smaller than it is; `nearest` gives each pixel the one texel under it, for pixel art.
- `projector` is an optional scene input whose camera projects the texture onto the surface instead, and `projector_occlusion` hides it where the projector can't see. See [camera projection](#camera-projection).

The texture is a raster like any other input, so an animated one is drawn again every frame and a static one is kept. A `material_3d` wired into many shapes shares one texture among them. Shapes showing a texture are drawn one by one under `instance_3d`, rather than from its instance buffer.

An object with nothing wired into `material` uses a lit, single-sided, white material, except an `image_plane_3d`, which uses an unlit, double-sided one. A wired `material_3d` applies exactly as it is set, with no defaults of the object's own, so a default `material_3d` makes an image plane lit and single-sided. Set its `unlit` and `double_sided` to keep the plane as it looks unwired.

Opaque objects hide what is behind them. Blended objects are drawn after the opaque ones, from back to front, ordered by their centres, and don't hide what is behind them. Blended objects that cross each other, or overlap while crossing in depth, can show in the wrong order.

A `model_3d` takes no `material_3d`. It uses the materials its glTF file defines instead, and its own `texture` and `projector` inputs replace one of them, as [a raster on a material](#a-raster-on-a-material) describes.

```json
{
  "nodes": [
    {
      "id": 0,
      "type": "material_3d",
      "params": { "color": "#e6b45a", "metallic": 1, "roughness": 0.2 }

    { "id": 1, "type": "shape_3d", "params": { "shape": "sphere", "position": [-2.4, 0, 0] } },
    { "id": 2, "type": "shape_3d", "params": { "shape": "sphere", "position": [-0.8, 0, 0] } },
```

```ts
import { Composition, nodes as n } from "@lumiscia/lumen-sdk";

const gold = n.material_3d({ color: "#e6b45a", metallic: 1, roughness: 0.2 });

const ball = (x: number, material: ReturnType<typeof n.material_3d>) =>
  n.shape_3d({ shape: "sphere", position: [x, 0, 0], material });

const composition = new Composition({ timeline: { durationSeconds: 3 } }).addOutput(
  n.render_3d({
    scene: n.merge_3d({
      objects: [
        ball(-2.4, gold),
        ball(-0.8, gold),
        ball(0.8, n.material_3d({ color: "#4aa3ff", opacity: 0.5 })),
        ball(2.4, n.material_3d({ color: "#ffffff", emissive: 1.5 })),
        n.camera_3d({ position: [0, 1, 7], look_at: true }),
      ],
    }),
  }),
);
```

### Cut-out cards

`alpha_mode: "mask"` draws a surface with the opaque objects, so it writes depth and is ordered by depth wherever cards cross, which a blended surface, ordered by its centre, can't be. A texel shows at full opacity when its alpha reaches `alpha_cutoff` (0.5 by default) and is discarded below it. The alpha tested is the colour's alpha times `opacity` times the texture's or raster's. Masked surfaces cast shadows shaped by the cut-out, and `render_3d`'s `supersample` antialiases the edges. It renders as a glTF `MASK` material does, so a `text` on an `image_plane_3d` with a masked material matches a model of a quad carrying the same image. It applies to every object that takes a `material_3d`, and takes precedence over an image plane's `opaque`. `shadow_catcher` can't be masked: a catcher's alpha sets its coverage, so the combination fails `check`.

```json
{
  "nodes": [
    {
      "id": 0,
      "type": "text",
      "params": {
        "content": "Lumen",
        "font_family": "Roboto",
        "font_size": 160,
        "color": "#e6b45a",
        "position": [420, 280]
      }
    },
    {
      "id": 1,
      "type": "material_3d",
      "params": { "unlit": true, "double_sided": true, "alpha_mode": "mask" }
    },
    {
      "id": 2,
      "type": "image_plane_3d",
      "params": { "width": 4, "sampling": "nearest", "rotation": [0, 25, 0] }
    },
    { "id": 3, "type": "render_3d" },
    { "id": 4, "type": "media_output" }
  ],
  "connections": [
    { "from_node": 0, "to_node": 2, "to_port": "source" },
    { "from_node": 1, "to_node": 2, "to_port": "material" },
    { "from_node": 2, "to_node": 3, "to_port": "scene" },
    { "from_node": 3, "to_node": 4, "to_port": "source" }
  ]
}
```

```ts
import { Composition, nodes as n } from "@lumiscia/lumen-sdk";

const composition = new Composition({ timeline: { durationSeconds: 3 } }).addOutput(
  n.render_3d({
    scene: n.image_plane_3d({
      source: n.text({
        content: "Lumen",
        font_family: "Roboto",
        font_size: 160,
        color: "#e6b45a",
        position: [420, 280],
      }),
      material: n.material_3d({ unlit: true, double_sided: true, alpha_mode: "mask" }),
      width: 4,
      sampling: "nearest",
      rotation: [0, 25, 0],
    }),
  }),
);
```

### Camera projection

A scene wired into a material's `projector` projects the material's `texture` from the scene's camera, chosen as `render_3d` chooses one, usually a `camera_3d` wired in alone. Each point of a surface takes the texel the projector sees it at, so a still or a plate lands on rough geometry as it was shot, and the camera the scene is drawn from can move around it: the standard 2.5D camera move. It needs only where the surface is and which way it faces, so it works on any object that takes a `material_3d` but an image plane, `instance_3d` copies included, and on a `model_3d` through its own `projector`.

- The texture fills the projector's view at its own aspect ratio, from the camera's `fov`, or `ortho_height` for an orthographic one, between its `near` and `far`.
- Faces turned away from the projector and points outside its view show the material's `color` alone, as if it had no texture.
- With `projector_occlusion`, on by default, so do points the projector can't see behind surfaces that cast shadows, found from a depth map drawn from the projector as a light's shadow map is. Each distinct projector draws one a frame, shared by every material projecting from it, and takes a tile of the shadow atlas. With it off the texture goes through what stands in front, as a slide projector's image would without its shadows.
- The texture is sampled with the material's `sampling`, filtered and mipmapped as a shape's texture is.
- The projector stands where its own scene places it, whatever places the objects, and is evaluated at the frame drawn, so an animated camera moves the projection. A plate wants a still `camera_3d` of its own, wired only into `projector`, apart from the camera the scene is drawn from.
- The texture's alpha counts where the material masks or blends, as it does through texture coordinates. Masked and blended surfaces cast shadows, and write depth and normal output, shaped by the projected alpha wherever the projector reaches, seen or not.
- A frame's materials project from at most 8 distinct projectors. A `projector` without a `texture` fails the render, naming the material.

## shape_3d

`shape_3d` makes a primitive centred on its `position`. `size` is its width, height and depth along X, Y and Z, before the rotation, and stretches the shape along each axis. The extents below are for the default `size` of `[1, 1, 1]`.

| `shape`    | Form                                                                                                       | Extent X × Y × Z |
| ---------- | ---------------------------------------------------------------------------------------------------------- | ---------------- |
| `box`      | A cuboid. The default.                                                                                     | 1 × 1 × 1        |
| `sphere`   | A sphere of diameter 1, an ellipsoid when `size` is uneven.                                                | 1 × 1 × 1        |
| `plane`    | A flat rectangle in the XZ plane facing +Y, a floor. It has no height, so `size` Y has no effect.          | 1 × 0 × 1        |
| `cylinder` | A cylinder along Y, with caps.                                                                             | 1 × 1 × 1        |
| `torus`    | A ring in the XZ plane. Its tube is a quarter as thick as the ring is wide, so its height is `size` Y ÷ 4. | 1 × 0.25 × 1     |
| `cone`     | A cone along Y, its point at +Y and its base, of diameter 1, at −Y.                                        | 1 × 1 × 1        |

A material's `texture` shows upright on the outside of each shape:

- `box`: the whole texture on each face. The top and bottom faces are upright to a camera on +Z that tilts to look at them.
- `plane`: the whole texture seen from above, its top edge toward −Z.
- `sphere`: wrapped equirectangularly around Y, its left edge at −Z and running toward −X, so a camera on +Z sees the texture's middle. The top row is at the top pole and the bottom row at the bottom one.
- `cylinder` and `cone`: the side is wrapped as the sphere is, from top to bottom. Each cap shows the circle inscribed in the texture, upright as on the box's top and bottom faces.
- `torus`: wrapped around Y as the sphere is, with the texture's height around the tube, from the inner equator over the top, so its middle row runs around the outer equator.

### Face materials

A box takes a `material_3d` for each face through `top_material`, `bottom_material`, `left_material`, `right_material`, `front_material` and `back_material`. They are the +Y, −Y, −X, +X, +Z and −Z faces in the box's own axes, before `rotation`, so `front_material` is the face toward the default camera, which looks down −Z. A face with no material wired uses `material`, and one with neither uses the default material.

A box with face materials is one node and one mesh, drawn as one object for each run of neighbouring faces that share a material, so a grass block with a green top costs two draws, not six shapes. Under `instance_3d` each run draws all its copies from the same instance buffer, and the instance's own placement applies to every face. Face materials on any other shape fail the render, naming the node and the input.

## render_3d

`render_3d` draws a scene into a raster the size of the composition. `width` and `height` set another size in pixels; 0 uses the composition's. Wire it into `merge`, `raster_multimerge` or any other 2D node.

- `supersample` renders 1 to 4 times wider and taller, then averages down, to antialias edges. It is 2 by default. It is lowered if the larger target would not fit the device.
- `exposure` adjusts the brightness in stops before tone mapping.
- `tone_mapping` is `none` (the default, which clips light above 1), `aces` or `agx`.
- `fog_density` fades surfaces into `fog_color` with distance: the fraction of their colour left after `d` world units is e^(−density × d). 0 turns fog off.
- `environment`, `environment_map` and the params that go with it are covered under [environment maps](#environment-maps).

### Reuse across frames

A node's output is reused on later frames while neither it nor anything it reads can change with the frame, so a `render_3d` of a still scene is drawn once. Reuse is on by default. A node counts as changing with the frame when it is:

- A node with an expression of its own, on the `render_3d` or on anything wired into it. An `instance_3d`'s expressions don't count unless they can differ between frames, as `time`, `frame`, `progress` and reads of another node's params can.
- A video source, a `wgsl_shader`, or an output node.
- A `model_3d` that plays a clip: `animation` set to a clip, even by a literal such as `"Walk"`, with `animation_speed` not 0. A clip that doesn't loop stops changing the model once it has ended, and the model is reused again from then on.

A `render_3d` of a posed model with no clip, over image planes whose sources are stills, is drawn once. The same scene with a video on one plane, or a looping clip, is drawn on every frame.

### Depth and normals

A `render_3d` has four outputs besides its default `output`: `color` (the lit scene), `depth`, `normal` and `matte`. A connection reads one with `from_port`, as `{ "from_node": 9, "from_port": "depth", "to_node": 11, "to_port": "mask" }`, or `outputOf(render, "depth")` in TypeScript. The `output` param picks what the default `output` holds, `color` unless it is set. One `render_3d` draws every output something reads with one walk of the scene, and draws nothing for the outputs nothing reads, so reading colour and depth from one node costs less than two `render_3d` nodes of the same scene.

- `depth` is the distance along the camera's view, from 0 at `depth_near` to 1 at `depth_far`, as opaque grey, and 1 where nothing is drawn. `depth_near` and `depth_far` are distances in world units; 0, the default, uses the camera's `near` or `far`. A negative or NaN distance, or one a 32-bit float can't hold, is a render error, and so is a `depth_far` that isn't past `depth_near`. Rasters hold 8 bits a channel, so depth has 256 steps between the two: set them around the part of the scene that matters.
- `normal` is the surface normal after normal maps, morph targets and skinning, in the camera's space: +X right, +Y up, +Z toward the camera. Each component `n` is stored as `n * 0.5 + 0.5`. The raster is opaque where a surface is drawn and transparent elsewhere.

Both record the nearest surface at each pixel that counts as solid:

- An opaque surface is solid everywhere. `text_3d` and every copy of an `instance_3d` are drawn like any other object, and a shadow catcher is solid too, since it hides what is behind it.
- A masked glTF material is solid where its alpha reaches its cutoff.
- A blended surface, such as an image plane or anything with `opacity` below 1, is solid only where its alpha is at least 0.5. The alpha is the base colour's, times a model's vertex alpha where it has one, times `opacity`, times the raster's or texture's. So a surface at `opacity` 0.4 writes nothing, and one at 0.5 writes where its raster is opaque. A blended surface that isn't solid at a pixel leaves what is behind it.

Where nothing is solid, `depth` is 1 and `normal` is transparent. Both are data: stored as they are, with no colour transfer function, and with no lighting, shadows or environment. They ignore `supersample`, so each pixel is the nearest surface at its centre.

### Mattes

`matte` selects objects of the rendered scene, so a 2D effect can treat them apart without rendering the scene twice. Each object takes a matte name from its `matte` param, and `render_3d`'s `mattes` lists up to four names, one for each channel of the `matte` output in turn: red, green, blue, then alpha. A channel holds the visible coverage of the objects with its name.

- `shape_3d`, `text_3d`, `extrude_3d`, `lathe_3d`, `image_plane_3d` and `model_3d` take a `matte` for what they draw. `merge_3d`, `instance_3d` and `particles_3d` take one for every object inside them that has none of its own, so the innermost name wins. An empty `matte`, the default, names nothing.
- Coverage is composited like colour. A surface covers its channel by its alpha, so a cut-out of a masked material covers nothing, and a surface in front hides the channels behind it by its own alpha: an object behind a plane at `opacity` 0.5 shows at 0.5, and behind an opaque one at 0. A shadow catcher covers its channel by how much it darkens.
- The matte is drawn with the colour, in the same draw, and averaged down with it by `supersample`, so its edges are antialiased and line up with the colour's. Reading it beside `color` costs one more pass at the output's size.
- It is data, not a picture: the channels are stored as they are and aren't premultiplied by the alpha, which is 0 unless `mattes` has a fourth name. `merge`'s `mask_mode` `red`, `green` or `blue` reads one channel as a mask, and `alpha` reads the fourth.
- More than four names, or a name listed twice, fails the render. A name no object takes leaves its channel 0, with a `scene.matte_unused` warning.

Here the title stays sharp while the rest of the scene blurs: the blurred colour is the base, and the sharp colour shows over it through the title's channel.

## Environment maps

`environment_map` on `render_3d` is an equirectangular Radiance `.hdr` or OpenEXR `.exr` file, a path or `asset:<id>`. It replaces the built-in studio: surfaces take their diffuse light and their reflections from it, rough ones blurred as much as their roughness.

- `environment` is the map's brightness. `environment_rotation` turns it about +Y in degrees.
- The map's centre is the view along −Z, with +X to its right and +Y at its top. A map that isn't 2:1 is stretched over the whole sphere.
- `environment_background` shows the map behind the scene, through the exposure and tone mapping but not the fog. The render is then opaque. `environment_background_blur`, from 0 (sharp) to 1, blurs it.
- Shadow catchers darken the background by the light their shadows take away.
- Non-finite and negative pixels are read as black.

A map is decoded and prefiltered the first time a render uses it, which takes about 0.35 s for a 2K or 4K map and 0.5 s for an 8K one. It is then cached on the GPU within a 256 MiB total, though maps the latest frame or a kept output used stay even past that, so turning it or changing its brightness reads nothing again while it stays there. Files over 256 MiB, maps over 8192 pixels a side or 8192 × 4096 in all, and EXR files with several parts, deep data or mip levels are refused. Larger maps are shrunk to 4096 × 2048 as they are read.

## image_plane_3d

`image_plane_3d` shows a raster on a flat rectangle facing +Z. Text, video, an image or any other 2D node can then sit in depth under a real camera. Wire the raster into `source`. For a video or an image, wire a `media_in`, or a `resize` of one.

- `width` is in world units, and the height follows the source's aspect ratio. A `text` or `shape` raster has the composition's size, so its plane has the composition's aspect ratio.
- With no `material_3d` wired into `material`, a plane is unlit and double-sided, so one that faces the camera shows its source's colours as in 2D, whatever `render_3d`'s `exposure` and `tone_mapping`. Seen from behind, the raster is mirrored.
- A `material_3d` applies exactly as it is set, so a default one makes the plane lit and single-sided, with the raster as its base colour. Set the material's `unlit` and `double_sided` to keep the plane as it was.
- A plane is blended: its transparent pixels show what is behind it. The material's `opacity` multiplies the source's alpha. A material whose `alpha_mode` is `mask` draws the plane as a [cut-out card](#cut-out-cards) instead. Planes are ordered by their centres, so keep layers apart in depth, and see the ordering note under [materials](#materials).
- `opaque` draws the plane with the opaque objects, writing depth, so it is ordered by depth against anything it crosses. Use it for a source with no transparent pixels. It ignores alpha.
- A source shown at its own size or larger keeps its detail. Shown smaller, it is filtered with mipmaps, then averaged by `supersample`.
- `sampling: "nearest"` shows pixel art unfiltered: each pixel gets the one texel under it, so texels stay hard-edged when magnified, and a plane shown smaller picks texels instead of averaging them, which can alias.
- `region`, `[x, y, width, height]` in the source's pixels, puts only that part of the source on a rectangle that covers just that part, where a `crop` before the plane would keep a raster the size of the source. The plane is where and as big as it is with the whole source on it, so a source cut into planes at different depths reads as one picture from where the camera sees them aligned. Planes with regions of one source share its texture and mip levels and draw together, and a region that changes every frame costs nothing more. Sampling is kept inside the region, so what is outside it isn't meant to show. Under strong minification the band along each edge of the region that is inside the source, and all of a very narrow region, is sampled from a sharper mip level than its footprint, because a texel of a shared level can hold pixels from both sides of the edge; that band can alias or shimmer where a `crop` would be smooth. A region is cut off at the source's edges, as `crop`'s is.

## model_3d

`model_3d` draws a glTF model: the default scene of a binary glTF (`.glb`) file, with its materials, and optionally one of its animation clips. `source` is a path or `asset:<id>`. The file must hold its buffers and images inside it. `position`, `rotation` and `scale` place the model like any other scene node. glTF is in metres, but models are often drawn at other scales, so set `scale` to fit.

### Animation

`animation` names the clip, by its name or its index. Empty plays none.

- A clip is at `time × animation_speed + animation_offset` seconds, with `animation_offset` in seconds. A negative `animation_speed` plays it backward.
- `animation_loop` is on by default and plays the clip again from its start once it ends. Off, the model holds the clip's last pose.
- A model with no clip (`animation` empty), or with `animation_speed` 0, and no expressions is reused across frames. A model with a clip is drawn on every frame until a clip that doesn't loop has ended. See [reuse across frames](#reuse-across-frames).

A clip, material or camera the model lacks fails the render with `render.node_evaluation`, and the message lists the ones it has. That is the quickest way to find the names in a file you don't know. `modelInfo` in `@lumiscia/lumen-bindings` lists them too, and a server that takes uploads returns them as the upload's `metadata`.

### The model's own lights and camera

A model's `KHR_lights_punctual` lights and cameras are left out unless you ask for them.

- `lights: true` adds the lights where the model's nodes place them. A directional light's intensity, in lux, and a point or spot light's, in candela, are used as `light_3d` intensities as they are. So a point light of intensity `I` lights a surface `d` metres away as a directional light of `I / d²` does. The lights cast no shadows, and a scene they light gets no default lights.
- `camera` views the scene from one of the model's cameras, by name or index. It is placed by the first node that places it, without that node's scale, and it counts as a `camera_3d` at the model, so the first camera in the scene still wins. The output's aspect ratio is used.

```json
    { "id": 2, "type": "media_output" }
  ],

    { "from_node": 0, "to_node": 1, "to_port": "scene" },
    { "from_node": 1, "to_node": 2, "to_port": "source" }
  ]
}
```

### What is read

- The default scene's node hierarchy, with each node's matrix or its translation, rotation and scale.
- Triangle meshes with their positions, normals, indices, vertex colours (`COLOR_0`) and two sets of texture coordinates. Faces without normals are lit flat. `KHR_mesh_quantization` attributes are read too.
- Metallic-roughness materials: base colour, metallic-roughness, normal, emissive and occlusion maps, with the normal scale and occlusion strength; opaque, mask and blend alpha modes; double-sided materials; `KHR_materials_unlit` and `KHR_materials_emissive_strength`. Vertex colours multiply the base colour.
- Each map's `KHR_texture_transform`, and the `texCoord` it names.
- PNG and JPEG textures with their samplers' wrap and filter modes.
- Skins, and animation clips of node translation, rotation, scale and morph weights, with step, linear and cubic-spline interpolation.
- Morph targets, as position and normal displacements, blended on the GPU by the mesh's default weights and by clips.
- `KHR_lights_punctual` lights and cameras, with `lights` and `camera`.
- Compressed files: Draco meshes, meshopt buffers, KTX2 (Basis Universal) and WebP textures. `lumen` and `lumen-server` read all four. The browser preview reads Draco, meshopt and WebP, and leaves KTX2 out because its transcoder would make the wasm about 350 KB larger to download. Its 2D-only build, from `@lumiscia/lumen-react/2d`, `@lumiscia/lumen-svelte/2d` or `@lumiscia/lumen-bindings/urls-2d`, has no 3D at all.

### What is not

| Left out                                                     | What happens                                                                                       |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| Points, lines, and triangle strips and fans                  | The model loads without them, with a `scene.model_primitives_skipped` warning.                     |
| A map naming a third set of texture coordinates              | The map is left out.                                                                               |
| Morph target tangent displacements                           | Ignored.                                                                                           |
| `.gltf` JSON files                                           | `media.unsupported`. Pack the model into a `.glb`.                                                 |
| Files outside the `.glb`, such as a separate `.bin` or image | `media.unsupported`. Only data inside the file, including `data:` URIs, is read.                   |
| A required extension not listed above                        | `media.unsupported`, naming it. An extension the file only uses, without requiring it, is skipped. |
| Draco meshes with morph targets                              | `media.unsupported`.                                                                               |
| Animated WebP textures                                       | `media.unsupported`.                                                                               |
| A file that is not a `.glb`, or is corrupt                   | `media.wrong_kind` or `media.decode`.                                                              |
| A file past a limit                                          | `media.too_large`.                                                                                 |

## text_3d

`text_3d` extrudes text into a solid. It shapes `content` as a `text` node with the same font and layout would, with its kerning, ligatures, font fallback and wrapping, then extrudes each glyph's outline `depth` deep along Z. It takes the `position`, `rotation` and `scale` of a `shape_3d`, and a `material_3d` through `material`; without one it is lit, single-sided and white.

- The text lies in the XY plane, facing +Z and reading along +X, centred on `position` by default. `alignment_horizontal` and `alignment_vertical` choose which point of its box sits at `position`.
- `font_size` is in world units, the height of the em square, so capitals are about 0.7 of it tall. `max_width`, `letter_spacing` and `line_height` are in world units too.
- `bevel_size` rounds the edges off, in world units and up to half of `depth`. `bevel_segments` is the steps of the rounding: 1 is a flat chamfer and 0 is no bevel.
- One style covers the whole text. Rich text spans, decorations, strokes and the `glyph_*` params of `text` have no counterpart.
- Glyphs drawn from colour or bitmap tables, such as emoji, have no outline, so they are left out with a `font.no_outlines` warning.
- `side_material` takes a `material_3d` for the glyphs' side walls and bevel. The front and back faces keep `material`, which the sides use too when `side_material` isn't wired. Wired, the two draw as two objects from one mesh.
- Glyph geometry is built again when the text, font, layout or bevel change. With a bevel on (`depth`, `bevel_size` and `bevel_segments` all above 0), changing `font_size` or `depth` builds it again too, because the bevel is sized against the font. Animating the transform or material costs no more than for a `shape_3d`.

## extrude_3d and lathe_3d

`extrude_3d` and `lathe_3d` turn a 2D outline into a solid. Wire a `path_2d`, `shape_2d` or `text_2d` into `geometry`, and a `material_3d` into `material`; without one the solid is lit, single-sided and white. Both take the `position`, `rotation` and `scale` of a `shape_3d`.

- **Coordinates.** The geometry's pixel coordinates, after its own `position`, `scale`, `rotation` and `anchor`, become world X and Y, `units_per_pixel` units each (0.01 by default, so 100 pixels is 1 unit), with Y flipped because 2D Y points down and 3D Y up. Pixel (0, 0) is the origin that the node's own `position`, `rotation` and `scale` move and turn the solid about. Nothing re-centres the outline on it, so the geometry's `position` and `anchor` decide where the solid sits about that origin: a `shape_2d` at the default `position` lies to the right of and below it. To centre a 200 by 100 pixel rectangle, give the `shape_2d` a `position` of `[-100, -50]`.
- **Curves.** A path or a text is flattened to within 0.001 world units, so a larger `units_per_pixel` keeps it as smooth, up to 16384 points. An ellipse gets as many sides as that takes for its radius, from 16 to 256, and each corner of a rounded rectangle a quarter of as many for its own radius.
- **Limits.** One solid takes at most 256 contours, 16384 points, 262144 vertices and 786432 indices. Past them the render fails, naming the node. A `text_2d` reaches 256 contours in a sentence or two; `text_3d` takes longer text.
- **Offsets.** An `offset_2d` anywhere in the geometry fails the render for now: `extrude_3d can't extrude an offset_2d outline yet; remove the offset_2d`. Bake the offset into the path instead.
- **Side material.** `extrude_3d` takes a `side_material` for its side walls and bevel, leaving the front and back caps to `material`, which the sides use too when `side_material` isn't wired. Wired, the two draw as two objects from one mesh. `lathe_3d` has no `side_material`.
- **Rebuilding.** A mesh is built once, and again only when the outline or the node's shape params change. Animating `position`, `rotation`, `scale`, the material or the `depth` of an extrusion without a bevel rebuilds nothing.

`extrude_3d` gives the outline `depth` along Z, centred on Z = 0, with its front cap facing +Z. It fills the outline by the nonzero rule, so a path's holes stay open whichever way they wind and overlapping subpaths join, and it closes open subpaths with a straight segment. `bevel_size` and `bevel_segments` round the edges off as on `text_3d`.

`lathe_3d` spins the outline around the world Y axis: a point's X is its distance from the axis, and its Y, flipped, its height. `segments` is the number of steps around a whole turn, and `sweep` under 360 degrees leaves an open wedge, from +X towards -Z, with no end caps.

- Points left of the axis are put on it.
- A closed contour makes a ring solid, with its faces pointing out of the area it encloses whichever way it winds. An open contour makes a surface, which is seen from both sides only if its material is `double_sided`.
- A point on the axis is a pole, where the surface closes to a point, as at the tip of a cone or the top of a dome. No triangle without area is left there, and a closed contour's edge along the axis draws nothing.
- Shading is smooth around the axis, and along the profile except at corners sharper than 30 degrees, which stay hard.
- Contours are spun separately: one inside another is a second solid, not a hole.

## instance_3d

`instance_3d` draws its input scene `count` times, from 0 to 100000. Copies share the input's meshes, textures, materials and skinned models' joint matrices on the GPU, so it costs far less than repeating the nodes.

Each copy is placed by `position`, `rotation` and `scale`, which are evaluated once per copy. The expression globals `instance`, the copy's index from 0, and `instance_count`, which is `count`, tell them apart. In the TypeScript SDK they are `instance` and `instanceCount`. They can be read only in this node's `position`, `rotation`, `scale` and `tint`. One node then lays out a grid, a ring or a path.

`tint` is a solid colour that multiplies the base colour of every object in a copy, so a white object takes the tint's colour and a textured one is coloured by it, and the light the object gives off, so a glowing copy glows in its tint. It is white by default. Like the placement it can be an expression evaluated once per copy, where `rgb(r, g, b)` makes a colour from components in 0 to 255; a literal is evaluated once. The tint's alpha is ignored, so a copy is opaque or blended exactly as its material makes it. The tints of nested `instance_3d` nodes multiply.

`copies` lists copies by hand instead, for placements that are fixed: an array of `{ position, rotation, scale, tint }`, where a field left out takes the default of the param of that name (position and rotation 0, scale 1, white). The list and every number in it are literals, and it holds at most 100000 copies. It is used in place of `count`, `position`, `rotation`, `scale` and `tint`, so `check` fails with one error naming them if any is set beside a list that has copies; an empty list places none of its own. The list is placed once, and copies of opaque surfaces are kept on the GPU, so their frames do no work per copy, which makes it cheaper than the same copies from expressions. Blended surfaces and those showing a raster are still copied one by one, as with `count`. Copies that animate keep using the expressions.

```json
          { "position": [2, 0, 1], "rotation": [0, 45, 0] }

    { "id": 2, "type": "render_3d" },
    { "id": 3, "type": "media_output" }

  "connections": [
    { "from_node": 0, "to_node": 1, "to_port": "scene" },
    { "from_node": 1, "to_node": 2, "to_port": "scene" },
    { "from_node": 2, "to_node": 3, "to_port": "source" }

}
```

- Only the input's objects are copied. Its lights and camera appear once, placed as they would be without the node.
- Every copy of a skinned model plays the same clip at the same time.
- An `instance_3d` may hold another, up to 8 deep, with their counts multiplied.
- `count` 0 leaves the scene out entirely, lights and camera too.

## particles_3d

`particles_3d` draws `count` copies of its `object` scene as particles, from 0 to 100000. With a scene wired into `surface`, each particle is emitted from a point picked at random over the surface's triangles, as likely anywhere as anywhere else of the same area, along the triangle's normal. Without one, particles are emitted from the node's origin along +Y. The surface isn't drawn, so wire it into a `merge_3d` as well to show it.

With the defaults, every particle is born at once and stays where it is emitted: a static scatter, such as grass on a hill or rocks on a floor. A `rate`, `lifetime` and `speed` make the node an emitter, such as sparks or snow:

- Particle `k` is born `k / rate` seconds into the composition, and born again somewhere new every `count / rate` seconds. A `rate` of 0 gives birth to all of them at 0 seconds, once.
- A particle lives `lifetime` seconds, and then draws nothing until it is born again. A `lifetime` of 0 lives until then, or forever when `rate` is 0. A `lifetime` longer than `count / rate` is cut short there, so raise `count` to keep particles longer at the same rate.
- A particle moves at `speed` along a direction picked within `spread` degrees of the normal, and falls with `gravity`: it is at `emit + velocity * age + gravity * age² / 2`. `gravity` is in the node's own space, which its `position` and `rotation` place.
- `scale` picks each particle's uniform scale between two values, and `scale_over_life` multiplies it from its first value at birth to its second at the end of its `lifetime`, which fades particles out without blending. `rotation_jitter` turns each particle at random, and `align_to_normal` stands its +Y along the normal it was emitted along.

A frame's particles depend only on the `seed`, the params, the surface and the time, which is the frame over the composition's frame rate. Any frame renders the same whether it is rendered alone, after the frames before it, or by another worker, and `motion_blur` blurs particles along their motion. They are placed on the GPU, so the CPU work of a frame doesn't grow with `count`.

- Each object of the surface emits in proportion to its area in the world, whatever its scale, so a flat plane or a flattened box still emits, and an `image_plane_3d` with a `region` emits from the part it shows. The surface is taken at rest: a skinned or morphed model emits from its vertices as stored, unposed. The copies of an `instance_3d` in the surface all emit. A surface with no area emits nothing.
- Particles are drawn as `instance_3d` copies are, all at once with no order among them, so the object's surfaces must be opaque or masked. A blended surface, or one showing a raster such as an image plane, fails the render, naming the node. The object's lights and camera are left out.
- Each `particles_3d` counts its object's objects once towards a scene's 100,000, however many particles it draws.
- A `particles_3d` under an `instance_3d` of `count` 1 is placed as a group would be. More copies of particles, particles of particles and particles emitted from particles fail the render.
- Particles cast and receive shadows. Where they can be is worked out from how far they can travel, at most `speed` times their age plus how far `gravity` takes them, so a fast or long-lived emitter spreads a directional light's shadow map over more of the scene.

## Limits

These are the limits a composition can reach, with what happens past them.

| Limit                                                               | Value                                                                                                             | Past it                                                                |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Objects in a frame's scene, counting every copy of an `instance_3d` | 100,000                                                                                                           | The render fails, naming the node.                                     |
| `instance_3d` `count`                                               | 0 to 100,000                                                                                                      | `check` reports `node.invalid_param`.                                  |
| `instance_3d` nested in `instance_3d`                               | 8 deep                                                                                                            | The render fails.                                                      |
| `particles_3d` `count`                                              | 0 to 100,000                                                                                                      | `check` reports `node.invalid_param`.                                  |
| Lights casting shadows in one `render_3d`                           | 8                                                                                                                 | The rest cast none, with `scene.shadow_limit`.                         |
| Distinct projectors in one frame's materials                        | 8                                                                                                                 | The render fails.                                                      |
| Lights in a model                                                   | 1024                                                                                                              | `media.too_large`.                                                     |
| `supersample`                                                       | 1 to 4                                                                                                            | Above 4 it is clamped to 4, and it is lowered if the target won't fit. |
| Joints and morph weights in one frame's skinned and morphed models  | 65,536 joints, 1,048,576 weights                                                                                  | The render fails.                                                      |
| A model's size                                                      | 4,000,000 vertices, 12,000,000 indices, 1024 joints a skin, 256 morph targets a mesh, textures 8192 pixels a side | `media.too_large`.                                                     |
| `text_3d`                                                           | The host's text glyph limit (16384 by default), 4,000,000 vertices, 12,000,000 indices                            | The render fails.                                                      |
| `extrude_3d` and `lathe_3d`                                         | 256 contours, 16384 points, 262,144 vertices, 786,432 indices                                                     | The render fails, naming the node.                                     |
| An environment map                                                  | 256 MiB, 8192 pixels a side, 8192 × 4096 in all                                                                   | The file is refused; larger maps are shrunk to 4096 × 2048.            |
| A `render_3d` output larger than the device allows                  | Set by the GPU                                                                                                    | The render fails.                                                      |

A model's own limits are the reader's, which `crates/3d/README.md` lists in full.

## Browser preview

The browser preview draws the same nodes with the same renderer, compiled to WebAssembly, and needs WebGPU. Pass each model's `.glb` file in `media`, under the name its `source` uses. [`packages/lumen-preview`](../packages/lumen-preview/README.md) describes the media a preview loads. A preview built without 3D support reports `node.unsupported` for a 3D node.

## Rendering without a browser

`lumen` renders a composition file on a GPU, and `lumen-server` takes the same compositions over HTTP. `lumen` has no asset store, so use paths under its media root, not `asset:` references. [`examples/README.md`](../examples/README.md) has the commands.
