# 3D

Lumen draws 3D scenes with the nodes of the `scene` category and `render_3d`, which turns a scene into an ordinary raster. Use them for objects seen by a real camera, glTF models, extruded text, and 2D layers placed in depth.

The [node reference](node-reference.md) lists every param. [`examples/README.md`](../examples/README.md) has three compositions you can render.

Each example below is the composition as JSON, then the TypeScript that builds it. The JSON shows `nodes` and `connections`; add `timeline` and `render_settings` as in any composition. Media names such as `fox.glb` stand for files you provide.

## Scene and raster ports

Every node input and output has a kind, `raster` or `scene`.

- A raster is an image: what `text`, `shape`, `media_in` and every other 2D node produces.
- A scene is objects, lights and cameras. `shape_3d`, `text_3d`, `image_plane_3d`, `model_3d`, `light_3d`, `camera_3d`, `merge_3d` and `instance_3d` output scenes.

An input takes only its own kind. Wiring a scene into a raster input, or a raster into a scene input, fails `check` with `connection.wrong_kind`.

`render_3d` is where a scene becomes a raster. It draws the scene on its `scene` input over a transparent background, so its output composites like any other layer. (`environment_background` shows the environment map behind the scene instead.) Going the other way, `image_plane_3d` and the `texture` input of `model_3d` take a raster into a scene.

`render_3d` draws one scene. To draw several objects, a light and a camera together, wire them all into one `merge_3d`, whose `objects` input takes any number of scenes. A camera and lights are scene nodes like any other.

```json
{
  "nodes": [
    { "id": 0, "type": "shape_3d", "params": { "color": "#e6b45a", "rotation": [20, 35, 0] } },
    { "id": 1, "type": "camera_3d", "params": { "position": [0, 1.5, 4], "look_at": true } },
    { "id": 2, "type": "merge_3d" },
    { "id": 3, "type": "render_3d" },
    { "id": 4, "type": "media_output" }
  ],
  "connections": [
    { "from_node": 0, "to_node": 2, "to_port": "objects" },
    { "from_node": 1, "to_node": 2, "to_port": "objects" },
    { "from_node": 2, "to_node": 3, "to_port": "scene" },
    { "from_node": 3, "to_node": 4, "to_port": "source" }
  ]
}
```

```ts
import { Composition, nodes as n } from "@lumiscia/lumen-sdk";

const composition = new Composition({ timeline: { durationSeconds: 3 } }).addOutput(
  n.render_3d({
    scene: n.merge_3d({
      objects: [
        n.shape_3d({ color: "#e6b45a", rotation: [20, 35, 0] }),
        n.camera_3d({ position: [0, 1.5, 4], look_at: true }),
      ],
    }),
  }),
);
```

## Units, axes and transforms

World units are metres. X points right, Y points up, and a camera looks down its own −Z, so +Z points toward the viewer.

`position`, `rotation` and `scale` are `[x, y, z]` values, so one expression can drive all three axes with `vec3(x, y, z)`.

- `rotation` is in degrees. It turns about Y first (yaw), then about the turned X (pitch), then about the turned Z (roll).
- `scale` multiplies along the object's own axes. A node applies its scale first, then its rotation, then its position.
- A child's transform is in its parent's space. `merge_3d` has `position`, `rotation` and `scale` of its own and places everything wired into it together, so nested merges build a hierarchy.

This group turns about Y, and its two shapes turn with it:

```json
{
  "nodes": [
    { "id": 0, "type": "shape_3d", "params": { "position": [1.2, 0, 0], "size": [0.8, 0.8, 0.8] } },
    {
      "id": 1,
      "type": "shape_3d",
      "params": { "shape": "sphere", "position": [-1.2, 0, 0], "size": [0.8, 0.8, 0.8] }
    },
    { "id": 2, "type": "merge_3d", "params": { "rotation": "=vec3(0, (time * 45), 0)" } },
    { "id": 3, "type": "camera_3d", "params": { "position": [0, 2, 5], "look_at": true } },
    { "id": 4, "type": "merge_3d" },
    { "id": 5, "type": "render_3d" },
    { "id": 6, "type": "media_output" }
  ],
  "connections": [
    { "from_node": 0, "to_node": 2, "to_port": "objects" },
    { "from_node": 1, "to_node": 2, "to_port": "objects" },
    { "from_node": 2, "to_node": 4, "to_port": "objects" },
    { "from_node": 3, "to_node": 4, "to_port": "objects" },
    { "from_node": 4, "to_node": 5, "to_port": "scene" },
    { "from_node": 5, "to_node": 6, "to_port": "source" }
  ]
}
```

```ts
import { Composition, nodes as n, time, vec3 } from "@lumiscia/lumen-sdk";

const composition = new Composition({ timeline: { durationSeconds: 4 } }).addOutput(
  n.render_3d({
    scene: n.merge_3d({
      objects: [
        n.merge_3d({
          rotation: vec3(0, time.mul(45), 0),
          objects: [
            n.shape_3d({ position: [1.2, 0, 0], size: [0.8, 0.8, 0.8] }),
            n.shape_3d({ shape: "sphere", position: [-1.2, 0, 0], size: [0.8, 0.8, 0.8] }),
          ],
        }),
        n.camera_3d({ position: [0, 2, 5], look_at: true }),
      ],
    }),
  }),
);
```

## Cameras

`camera_3d` is the viewpoint `render_3d` draws from.

- `projection` is `perspective` (the default) or `orthographic`. A perspective camera has a vertical `fov` in degrees, 40 by default. An orthographic one shows a view `ortho_height` world units tall, and things keep their size at any distance.
- The view's width follows the aspect ratio of `render_3d`'s output.
- `near` and `far` bound what is drawn, 0.05 and 1000 by default.
- `position` is 5 units along +Z by default. Aim the camera with `rotation`, or turn on `look_at` to aim it at `target`, which then ignores `rotation`. With `look_at`, the camera's up direction is +Y, or Z when it aims almost straight up or down.
- The first camera in a scene is the one used, in the order the objects are wired. A scene with no camera is seen from `[0, 0, 5]` with a 40° field of view.
- A glTF model's own camera counts as a `camera_3d` placed at the model. See [model_3d](#model_3d).

An orbiting camera uses an expression for `position`:

```json
{
  "nodes": [
    {
      "id": 0,
      "type": "shape_3d",
      "params": { "shape": "torus", "color": "#4aa3ff", "metallic": 1, "roughness": 0.3 }
    },
    {
      "id": 1,
      "type": "camera_3d",
      "params": { "position": "=vec3((sin(time) * 4), 1.5, (cos(time) * 4))", "look_at": true }
    },
    { "id": 2, "type": "merge_3d" },
    { "id": 3, "type": "render_3d", "params": { "tone_mapping": "agx" } },
    { "id": 4, "type": "media_output" }
  ],
  "connections": [
    { "from_node": 0, "to_node": 2, "to_port": "objects" },
    { "from_node": 1, "to_node": 2, "to_port": "objects" },
    { "from_node": 2, "to_node": 3, "to_port": "scene" },
    { "from_node": 3, "to_node": 4, "to_port": "source" }
  ]
}
```

```ts
import { Composition, cos, nodes as n, sin, time, vec3 } from "@lumiscia/lumen-sdk";

const composition = new Composition({ timeline: { durationSeconds: 6 } }).addOutput(
  n.render_3d({
    scene: n.merge_3d({
      objects: [
        n.shape_3d({ shape: "torus", color: "#4aa3ff", metallic: 1, roughness: 0.3 }),
        n.camera_3d({
          position: vec3(sin(time).mul(4), 1.5, cos(time).mul(4)),
          look_at: true,
        }),
      ],
    }),
    tone_mapping: "agx",
  }),
);
```

## Lights

`light_3d` has four kinds:

| `light`       | Shines                                                                                                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `directional` | In parallel along the light's −Z, like the sun. Its `position` has no effect.                                                                                                |
| `point`       | Every way from its `position`. `range` is the distance past which it has no effect, as for a spot light; 0 is unlimited.                                                     |
| `spot`        | In a cone along the light's −Z from its `position`. `spot_angle` is the cone's full angle in degrees, and `spot_softness` the fraction of it, from the edge, that fades out. |
| `ambient`     | Evenly on every surface from all around. Its `position` and `rotation` have no effect.                                                                                       |

`color` and `intensity` set the light. `intensity` is a unitless multiplier, 3 by default, and point and spot lights fall off with the square of the distance. The default `rotation` of every light is `[-45, 30, 0]`, which points a directional or spot light 45° down.

A scene with no lights gets a default key light and an ambient fill. A scene lit by an [environment map](#environment-maps) and no lights gets none.

`render_3d` also lights every surface from all around with an environment, a built-in studio unless you set `environment_map`. It gives metals something to reflect. Its `environment` param is the brightness of that light, and 0 turns it off.

### Shadows

Turn on `cast_shadows` on a directional, spot or point light, and objects between it and others block its light.

- `shadow_softness` is how wide shadow edges blur, in world units. It is 0.02 by default.
- A directional light's shadows cover what the camera sees out to `shadow_distance`, 50 by default, measured from the camera along its view. A larger distance trades sharpness for reach.
- A spot light's shadows cover its cone, up to 170° across.
- A `render_3d` draws shadows for the first 8 lights casting them, in the order its scene inputs are wired. The rest light the scene without shadows, with a `scene.shadow_limit` warning.

`shape_3d`, `text_3d`, `image_plane_3d` and `model_3d` take `cast_shadows` and `receive_shadows`, both on by default. Unlit and glowing surfaces cast shadows too, so a shape that stands in for a light, such as a bulb around a point light, needs `cast_shadows` off.

`shadow_catcher` on a `shape_3d`, `text_3d` or `image_plane_3d` shows nothing but the shadows falling on it. It darkens what the render is composited over by the light the shadows take away. That puts a shadow under an object on 2D footage:

## Materials

`shape_3d`, `text_3d` and `image_plane_3d` share their material params:

- `color` is the base colour. It must be a solid colour, not a gradient. An image plane multiplies its raster by it.
- `metallic` is 0 for a dielectric such as plastic and 1 for a bare metal. `roughness` is 0 for a mirror finish and 1 for fully diffuse. Both run from 0 to 1.
- `emissive` is light the surface gives off, as a multiple of its base colour.
- `opacity` multiplies the alpha. Anything below 1 is drawn blended.
- `unlit` shows the base colour as it is, ignoring lights.
- `double_sided` draws the back of each face too. It is off for shapes and text, so a single-sided face is invisible from behind, and on for image planes.

Opaque objects hide what is behind them. Blended objects are drawn after the opaque ones, from back to front, ordered by their centres, and don't hide what is behind them. Blended objects that cross each other, or overlap while crossing in depth, can show in the wrong order.

A `model_3d` uses the materials its glTF file defines instead.

## shape_3d

`shape_3d` makes a primitive centred on its `position`. `size` is its width, height and depth along X, Y and Z, before the rotation, and stretches the shape along each axis. The extents below are for the default `size` of `[1, 1, 1]`.

| `shape`    | Form                                                                                                       | Extent X × Y × Z |
| ---------- | ---------------------------------------------------------------------------------------------------------- | ---------------- |
| `box`      | A cuboid. The default.                                                                                     | 1 × 1 × 1        |
| `sphere`   | A sphere of diameter 1, an ellipsoid when `size` is uneven.                                                | 1 × 1 × 1        |
| `plane`    | A flat rectangle in the XZ plane facing +Y, a floor. It has no height, so `size` Y has no effect.          | 1 × 0 × 1        |
| `cylinder` | A cylinder along Y, with caps.                                                                             | 1 × 1 × 1        |
| `torus`    | A ring in the XZ plane. Its tube is a quarter as thick as the ring is wide, so its height is `size` Y ÷ 4. | 1 × 0.25 × 1     |
| `cone`     | A cone along Y, its point at +Y and its base, of diameter 1, at −Y.                                        | 1 × 1 × 1        |

## render_3d

`render_3d` draws a scene into a raster the size of the composition. `width` and `height` set another size in pixels; 0 uses the composition's. Wire it into `merge`, `raster_multimerge` or any other 2D node.

- `supersample` renders 1 to 4 times wider and taller, then averages down, to antialias edges. It is 2 by default. It is lowered if the larger target would not fit the device.
- `exposure` adjusts the brightness in stops before tone mapping.
- `tone_mapping` is `none` (the default, which clips light above 1), `aces` or `agx`.
- `fog_density` fades surfaces into `fog_color` with distance: the fraction of their colour left after `d` world units is e^(−density × d). 0 turns fog off.
- `environment`, `environment_map` and the params that go with it are covered under [environment maps](#environment-maps).

### Reuse across frames

A node's output is reused on later frames while neither it nor anything it reads can change with the frame, so a `render_3d` of a still scene is drawn once. Reuse is on by default. A node counts as changing with the frame when it is:

- A node with an expression of its own, on the `render_3d` or on anything wired into it. An `instance_3d`'s expressions don't count unless they can differ between frames, as `time`, `frame`, `progress` and reads of another node's params can.
- A video source, a `wgsl_shader`, or an output node.
- A `model_3d` that plays a clip: `animation` set to a clip, even by a literal such as `"Walk"`, with `animation_speed` not 0. A clip that doesn't loop stops changing the model once it has ended, and the model is reused again from then on.

A `render_3d` of a posed model with no clip, over image planes whose sources are stills, is drawn once. The same scene with a video on one plane, or a looping clip, is drawn on every frame.

### Depth and normals

`output` picks what the raster holds: `color` (the lit scene, the default), `depth` or `normal`. A node has one output, so a composition that wants colour and depth draws the same scene with two `render_3d` nodes. The second shares the models, meshes and image-plane sources the first loaded.

- `depth` is the distance along the camera's view, from 0 at `depth_near` to 1 at `depth_far`, as opaque grey, and 1 where nothing is drawn. `depth_near` and `depth_far` are distances in world units; 0, the default, uses the camera's `near` or `far`. A negative or NaN distance, or one a 32-bit float can't hold, is a render error, and so is a `depth_far` that isn't past `depth_near`. Rasters hold 8 bits a channel, so depth has 256 steps between the two: set them around the part of the scene that matters.
- `normal` is the surface normal after normal maps, morph targets and skinning, in the camera's space: +X right, +Y up, +Z toward the camera. Each component `n` is stored as `n * 0.5 + 0.5`. The raster is opaque where a surface is drawn and transparent elsewhere.

Both record the nearest surface at each pixel that counts as solid:

- An opaque surface is solid everywhere. `text_3d` and every copy of an `instance_3d` are drawn like any other object, and a shadow catcher is solid too, since it hides what is behind it.
- A masked glTF material is solid where its alpha reaches its cutoff.
- A blended surface, such as an image plane or anything with `opacity` below 1, is solid only where its alpha is at least 0.5. The alpha is the base colour's, times a model's vertex alpha where it has one, times `opacity`, times the raster's or texture's. So a surface at `opacity` 0.4 writes nothing, and one at 0.5 writes where its raster is opaque. A blended surface that isn't solid at a pixel leaves what is behind it.

Where nothing is solid, `depth` is 1 and `normal` is transparent. Both are data: stored as they are, with no colour transfer function, and with no lighting, shadows or environment. They ignore `supersample`, so each pixel is the nearest surface at its centre.

```ts
  n.shape_3d({

    position: [i % 2 === 0 ? -1 : 1, 0.8, -i * 2.5],
    color: "#d94b4b",
  }),
);
const scene = n.merge_3d({
  objects: [...posts, n.camera_3d({ position: [0, 1.5, 6], look_at: true })],
});

const composition = new Composition({ timeline: { durationSeconds: 2 } }).addOutput(
  n.merge({
    base: n.render_3d({ scene }),
    overlay: n.background({ paint: [205, 215, 228, 255] }),
    mask: n.render_3d({ scene, output: "depth", depth_near: 3, depth_far: 20 }),
    mask_mode: "luma",
  }),
);
```

## Environment maps

`environment_map` on `render_3d` is an equirectangular Radiance `.hdr` or OpenEXR `.exr` file, a path or `asset:<id>`. It replaces the built-in studio: surfaces take their diffuse light and their reflections from it, rough ones blurred as much as their roughness.

- `environment` is the map's brightness. `environment_rotation` turns it about +Y in degrees.
- The map's centre is the view along −Z, with +X to its right and +Y at its top. A map that isn't 2:1 is stretched over the whole sphere.
- `environment_background` shows the map behind the scene, through the exposure and tone mapping but not the fog. The render is then opaque. `environment_background_blur`, from 0 (sharp) to 1, blurs it.
- Shadow catchers darken the background by the light their shadows take away.
- Non-finite and negative pixels are read as black.

A map is decoded and prefiltered the first time a render uses it, which takes about 0.35 s for a 2K or 4K map and 0.5 s for an 8K one. It is then cached on the GPU within a 256 MiB total, though maps the latest frame or a kept output used stay even past that, so turning it or changing its brightness reads nothing again while it stays there. Files over 256 MiB, maps over 8192 pixels a side or 8192 × 4096 in all, and EXR files with several parts, deep data or mip levels are refused. Larger maps are shrunk to 4096 × 2048 as they are read.

```json
{
  "nodes": [
    {
      "id": 0,
      "type": "shape_3d",
      "params": { "shape": "sphere", "color": "#ffffff", "metallic": 1, "roughness": 0.05 }
    },
    { "id": 1, "type": "camera_3d", "params": { "position": [0, 0.4, 3], "look_at": true } },
    { "id": 2, "type": "merge_3d" },
    {
      "id": 3,
      "type": "render_3d",
      "params": {
        "environment_map": "studio.hdr",
        "environment_rotation": 90,
        "environment_background": true,
        "environment_background_blur": 0.3
      }
    },
    { "id": 4, "type": "media_output" }
  ],
  "connections": [
    { "from_node": 0, "to_node": 2, "to_port": "objects" },
    { "from_node": 1, "to_node": 2, "to_port": "objects" },
    { "from_node": 2, "to_node": 3, "to_port": "scene" },
    { "from_node": 3, "to_node": 4, "to_port": "source" }
  ]
}
```

```ts

  }),

```

## image_plane_3d

`image_plane_3d` shows a raster on a flat rectangle facing +Z. Text, video, an image or any other 2D node can then sit in depth under a real camera. Wire the raster into `source`. For a video or an image, wire a `media_in`, or a `resize` of one.

- `width` is in world units, and the height follows the source's aspect ratio. A `text` or `shape` raster has the composition's size, so its plane has the composition's aspect ratio.
- A plane is `unlit` and `double_sided` by default, so one that faces the camera shows its source's colours as in 2D, whatever `render_3d`'s `exposure` and `tone_mapping`. Seen from behind, the raster is mirrored.
- Set `unlit` to false to light the plane, with the raster as its base colour.
- A plane is blended: its transparent pixels show what is behind it. `opacity` multiplies the source's alpha. Planes are ordered by their centres, so keep layers apart in depth, and see the ordering note under [materials](#materials).
- `opaque` draws the plane with the opaque objects, writing depth, so it is ordered by depth against anything it crosses. Use it for a source with no transparent pixels. It ignores alpha.
- A source shown at its own size or larger keeps its detail. Shown smaller, it is filtered with mipmaps, then averaged by `supersample`.

[`examples/3d/src/layers.ts`](../examples/3d/src/layers.ts) stacks layers at different depths under a moving camera.

## model_3d

`model_3d` draws a glTF model: the default scene of a binary glTF (`.glb`) file, with its materials, and optionally one of its animation clips. `source` is a path or `asset:<id>`. The file must hold its buffers and images inside it. `position`, `rotation` and `scale` place the model like any other scene node. glTF is in metres, but models are often drawn at other scales, so set `scale` to fit.

### Animation

`animation` names the clip, by its name or its index. Empty plays none.

- A clip is at `time × animation_speed + animation_offset` seconds, with `animation_offset` in seconds. A negative `animation_speed` plays it backward.
- `animation_loop` is on by default and plays the clip again from its start once it ends. Off, the model holds the clip's last pose.
- A model with no clip (`animation` empty), or with `animation_speed` 0, and no expressions is reused across frames. A model with a clip is drawn on every frame until a clip that doesn't loop has ended. See [reuse across frames](#reuse-across-frames).

A clip, material or camera the model lacks fails the render with `render.node_evaluation`, and the message lists the ones it has. That is the quickest way to find the names in a file you don't know. `modelInfo` in `@lumiscia/lumen-bindings` lists them too, and a server that takes uploads returns them as the upload's `metadata`.

```json
{
  "nodes": [
    {
      "id": 0,
      "type": "model_3d",
      "params": {
        "source": "fox.glb",

        "rotation": [0, 90, 0]
      }

      "id": 1,

    { "from_node": 0, "to_node": 2, "to_port": "objects" },
    { "from_node": 1, "to_node": 2, "to_port": "objects" },
    { "from_node": 2, "to_node": 3, "to_port": "scene" },
    { "from_node": 3, "to_node": 4, "to_port": "source" }

```

### The model's own lights and camera

A model's `KHR_lights_punctual` lights and cameras are left out unless you ask for them.

- `lights: true` adds the lights where the model's nodes place them. A directional light's intensity, in lux, and a point or spot light's, in candela, are used as `light_3d` intensities as they are. So a point light of intensity `I` lights a surface `d` metres away as a directional light of `I / d²` does. The lights cast no shadows, and a scene they light gets no default lights.
- `camera` views the scene from one of the model's cameras, by name or index. It is placed by the first node that places it, without that node's scale, and it counts as a `camera_3d` at the model, so the first camera in the scene still wins. The output's aspect ratio is used.

```json
{
  "nodes": [
    {
      "id": 0,
      "type": "model_3d",
      "params": { "source": "robot.glb", "animation": "Talk", "lights": true, "camera": "Closeup" }
    },
    { "id": 1, "type": "render_3d" },
    { "id": 2, "type": "media_output" }
  ],
  "connections": [
    { "from_node": 0, "to_node": 1, "to_port": "scene" },
    { "from_node": 1, "to_node": 2, "to_port": "source" }
  ]
}
```

```ts
import { Composition, nodes as n } from "@lumiscia/lumen-sdk";

const composition = new Composition({ timeline: { durationSeconds: 4 } }).addOutput(
  n.render_3d({
    scene: n.model_3d({ source: "robot.glb", animation: "Talk", lights: true, camera: "Closeup" }),
  }),
);
```

### What is read

- The default scene's node hierarchy, with each node's matrix or its translation, rotation and scale.
- Triangle meshes with their positions, normals, indices, vertex colours (`COLOR_0`) and two sets of texture coordinates. Faces without normals are lit flat. `KHR_mesh_quantization` attributes are read too.
- Metallic-roughness materials: base colour, metallic-roughness, normal, emissive and occlusion maps, with the normal scale and occlusion strength; opaque, mask and blend alpha modes; double-sided materials; `KHR_materials_unlit` and `KHR_materials_emissive_strength`. Vertex colours multiply the base colour.
- Each map's `KHR_texture_transform`, and the `texCoord` it names.
- PNG and JPEG textures with their samplers' wrap and filter modes.
- Skins, and animation clips of node translation, rotation, scale and morph weights, with step, linear and cubic-spline interpolation.
- Morph targets, as position and normal displacements, blended on the GPU by the mesh's default weights and by clips.
- `KHR_lights_punctual` lights and cameras, with `lights` and `camera`.
- Compressed files: Draco meshes, meshopt buffers, KTX2 (Basis Universal) and WebP textures. `lumen` and `lumen-server` read all four. The WebAssembly bindings' default build reads meshopt only.

### What is not

| Left out                                                     | What happens                                                                                       |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| Points, lines, and triangle strips and fans                  | The model loads without them, with a `scene.model_primitives_skipped` warning.                     |
| A map naming a third set of texture coordinates              | The map is left out.                                                                               |
| Morph target tangent displacements                           | Ignored.                                                                                           |
| `.gltf` JSON files                                           | `media.unsupported`. Pack the model into a `.glb`.                                                 |
| Files outside the `.glb`, such as a separate `.bin` or image | `media.unsupported`. Only data inside the file, including `data:` URIs, is read.                   |
| A required extension not listed above                        | `media.unsupported`, naming it. An extension the file only uses, without requiring it, is skipped. |
| Draco meshes with morph targets                              | `media.unsupported`.                                                                               |
| Animated WebP textures                                       | `media.unsupported`.                                                                               |
| A file that is not a `.glb`, or is corrupt                   | `media.wrong_kind` or `media.decode`.                                                              |
| A file past a limit                                          | `media.too_large`.                                                                                 |

## text_3d

`text_3d` extrudes text into a solid. It shapes `content` as a `text` node with the same font and layout would, with its kerning, ligatures, font fallback and wrapping, then extrudes each glyph's outline `depth` deep along Z. It takes the `position`, `rotation`, `scale` and material params of a `shape_3d`.

- The text lies in the XY plane, facing +Z and reading along +X, centred on `position` by default. `alignment_horizontal` and `alignment_vertical` choose which point of its box sits at `position`.
- `font_size` is in world units, the height of the em square, so capitals are about 0.7 of it tall. `max_width`, `letter_spacing` and `line_height` are in world units too.
- `bevel_size` rounds the edges off, in world units and up to half of `depth`. `bevel_segments` is the steps of the rounding: 1 is a flat chamfer and 0 is no bevel.
- One style covers the whole text. Rich text spans, decorations, strokes and the `glyph_*` params of `text` have no counterpart.
- Glyphs drawn from colour or bitmap tables, such as emoji, have no outline, so they are left out with a `font.no_outlines` warning.
- Glyph geometry is built again when the text, font, layout or bevel change. With a bevel on (`depth`, `bevel_size` and `bevel_segments` all above 0), changing `font_size` or `depth` builds it again too, because the bevel is sized against the font. Animating the transform or material costs no more than for a `shape_3d`.


## instance_3d

`instance_3d` draws its input scene `count` times, from 0 to 100000. Copies share the input's meshes, textures, materials and skinned models' joint matrices on the GPU, so it costs far less than repeating the nodes.

Each copy is placed by `position`, `rotation` and `scale`, which are evaluated once per copy. The expression globals `instance`, the copy's index from 0, and `instance_count`, which is `count`, tell them apart. In the TypeScript SDK they are `instance` and `instanceCount`. They can be read only in this node's `position`, `rotation` and `scale`. One node then lays out a grid, a ring or a path.

- A copy is placed in the input scene's own space, so it turns and scales about that scene's origin.
- Only the input's objects are copied. Its lights and camera appear once, placed as they would be without the node.
- Every copy of a skinned model plays the same clip at the same time.
- An `instance_3d` may hold another, up to 8 deep, with their counts multiplied.
- `count` 0 leaves the scene out entirely, lights and camera too.

```json
{
  "nodes": [
    { "id": 0, "type": "shape_3d", "params": { "size": [0.6, 0.6, 0.6], "position": [0, 0.3, 0] } },
    {
      "id": 1,
      "type": "instance_3d",
      "params": {
        "count": 100,
        "position": "=vec3(instance % 10 * 1.5 - 6.75, 0, floor(instance / 10) * 1.5 - 6.75)"
      }
    },
    { "id": 2, "type": "camera_3d", "params": { "position": [0, 9, 12], "look_at": true } },
    { "id": 3, "type": "merge_3d" },
    { "id": 4, "type": "render_3d" },
    { "id": 5, "type": "media_output" }
  ],
  "connections": [
    { "from_node": 0, "to_node": 1, "to_port": "scene" },
    { "from_node": 1, "to_node": 3, "to_port": "objects" },
    { "from_node": 2, "to_node": 3, "to_port": "objects" },
    { "from_node": 3, "to_node": 4, "to_port": "scene" },
    { "from_node": 4, "to_node": 5, "to_port": "source" }
  ]
}
```

```ts
import { Composition, expr, instance, nodes as n } from "@lumiscia/lumen-sdk";

const composition = new Composition({ timeline: { durationSeconds: 3 } }).addOutput(
  n.render_3d({
    scene: n.merge_3d({
      objects: [
        n.instance_3d({
          count: 100,
          position: expr`vec3(${instance} % 10 * 1.5 - 6.75, 0, floor(${instance} / 10) * 1.5 - 6.75)`,
          scene: n.shape_3d({ size: [0.6, 0.6, 0.6], position: [0, 0.3, 0] }),
        }),
        n.camera_3d({ position: [0, 9, 12], look_at: true }),
      ],
    }),
  }),
);
```

## Limits

These are the limits a composition can reach, with what happens past them.

| Limit                                                               | Value                                                                                                             | Past it                                                                |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Objects in a frame's scene, counting every copy of an `instance_3d` | 100,000                                                                                                           | The render fails, naming the node.                                     |
| `instance_3d` `count`                                               | 0 to 100,000                                                                                                      | `check` reports `node.invalid_param`.                                  |
| `instance_3d` nested in `instance_3d`                               | 8 deep                                                                                                            | The render fails.                                                      |
| Lights casting shadows in one `render_3d`                           | 8                                                                                                                 | The rest cast none, with `scene.shadow_limit`.                         |
| Lights in a model                                                   | 1024                                                                                                              | `media.too_large`.                                                     |
| `supersample`                                                       | 1 to 4                                                                                                            | Above 4 it is clamped to 4, and it is lowered if the target won't fit. |
| Joints and morph weights in one frame's skinned and morphed models  | 65,536 joints, 1,048,576 weights                                                                                  | The render fails.                                                      |
| A model's size                                                      | 4,000,000 vertices, 12,000,000 indices, 1024 joints a skin, 256 morph targets a mesh, textures 8192 pixels a side | `media.too_large`.                                                     |
| `text_3d`                                                           | The host's text glyph limit (16384 by default), 4,000,000 vertices, 12,000,000 indices                            | The render fails.                                                      |
| An environment map                                                  | 256 MiB, 8192 pixels a side, 8192 × 4096 in all                                                                   | The file is refused; larger maps are shrunk to 4096 × 2048.            |
| A `render_3d` output larger than the device allows                  | Set by the GPU                                                                                                    | The render fails.                                                      |

A model's own limits are the reader's, which `crates/3d/README.md` lists in full.

## Browser preview

The browser preview draws the same nodes with the same renderer, compiled to WebAssembly, and needs WebGPU. Pass each model's `.glb` file in `media`, under the name its `source` uses. [`packages/lumen-preview`](../packages/lumen-preview/README.md) describes the media a preview loads. A preview built without 3D support reports `node.unsupported` for a 3D node.

## Rendering without a browser

`lumen` renders a composition file on a GPU, and `lumen-server` takes the same compositions over HTTP. `lumen` has no asset store, so use paths under its media root, not `asset:` references. [`examples/README.md`](../examples/README.md) has the commands.
