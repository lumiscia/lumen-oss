# lumen-server

`lumen-server` provides the Lumen render library plus a small local HTTP binary.

For production usage, the smoothest path is the hosted platform at [lumiscia.com](https://lumiscia.com). Self-hosting this crate is possible, but you will still need GPU machines, queueing, artifact storage, auth, deployment, and monitoring.

This crate is experimental and its library API may change.

## Platform Notes

Native rendering requires a GPU.

Supported targets today are:

- Linux with Vulkan rendering and optional CUDA/NVENC interop when built with `vulkan,cuda`.
- macOS with Metal rendering and VideoToolbox-oriented media paths when built with `metal`.

## Targets

`lumen-server` ships both:

- a library target, `lumen_server`, whose `render` module renders a project payload to an MP4 for embedding in custom render platforms
- a binary target, `lumen-server`, for local HTTP rendering

The exposed Axum API is intentionally binary-owned. The HTTP binary accepts the same public render payload shape as the hosted Lumen API:

```json
{
  "composition": {
    "timeline": { "fps": 30, "duration_frames": 120 },
    "render_settings": { "width": 1280, "height": 720 },
    "nodes": [
      { "id": 1, "type": "media_in", "params": { "kind": "image", "source": "hero" } },
      { "id": 2, "type": "media_output" }
    ],
    "connections": [{ "from_node": 1, "from_port": "output", "to_node": 2, "to_port": "source" }]
  },
  "media": {
    "hero": "https://example.com/hero.png"
  }
}
```

Inside the composition, media nodes and audio clips should reference the manifest aliases (`"hero"`), not the URLs directly. The hosted API uses the same alias pattern, but its manifest values are uploaded media references like `lumen:<media_id>`. The self-hosted server does not implement media upload APIs, artifact staging, provider progress callbacks, billing, accounts, durable queueing, or durable artifact storage; it downloads direct `http`/`https` media URLs, renders in a local background task, stores the MP4 artifact in memory, and exposes it at `GET /renders/:id/artifact`.

`POST /renders` validates the request before accepting it. A composition that does not parse, or an invalid manifest, returns `422`. `webhookUrl` returns `400` with the code `webhooks_unsupported`, because this server does not deliver webhooks. A body over 2 MiB returns `413` with the code `request_too_large`, and a body that is not the expected JSON returns the matching `4xx` with the code `invalid_request_body`. Render IDs are always generated by the server.

A failed request answers with its status and `{ "code": "...", "error": "..." }`.

A render that fails after being accepted keeps why. `GET /renders/:id` and `GET /renders/:id/progress` return it as `render.error`: `{ "code": "...", "message": "...", "retryable": false }`. The `progress` object has the same as `error`, `errorCode` and `retryable`, and the WebSocket's `render.failed` event carries it as `error`.

S3-compatible artifact storage is planned for a future self-hosted release. For now, the HTTP binary's in-memory artifact storage is intended for local development and single-process testing, not durable production delivery. Only the most recent `--retained-renders` finished renders (default 16, `LUMEN_SERVER_RETAINED_RENDERS`) are kept, and their artifacts stay in memory until then. Older renders are dropped, record and artifact together, and return `404`.

Renders run in submission order, `--max-concurrent-renders` at a time (default 1, `LUMEN_SERVER_MAX_CONCURRENT_RENDERS`). Later renders stay `queued` until a slot frees. Raise it only if the GPU has the memory for parallel renders.

### Media and fonts

A render reads media from one place: a directory created for that job, holding only the files downloaded from its manifest. A composition without a manifest gets an empty directory, so any source that is not a manifest alias fails, including relative paths, absolute paths, and `file://` URLs. Sources are matched after resolving symlinks.

Video and audio are only read from containers that keep their data inside the file:

- **Video:** MP4 and MOV, plus Matroska and WebM, MPEG-TS, MPEG-PS, AVI, FLV, ASF/WMV, Ogg, MXF, and IVF. Raw H.264 and HEVC streams carry no duration, so they fail to open. Put them in a container first.
- **Audio:** MP3, AAC, WAV, W64, FLAC, AIFF, CAF, AC-3, E-AC-3, DTS, AMR, and WavPack, plus the audio forms of the containers above.
- **Stills read as video:** PNG, JPEG, WebP, BMP, and TIFF hold one frame for the whole clip. GIF and APNG play their animation. Other image formats, such as TGA, EXR, and SVG, are refused.

Formats that point at other files or hosts are refused, including HLS, DASH, concat lists, image sequences, and SDP, because they could read outside the job directory. Images on `media_in` nodes with `kind: "image"` are decoded from their bytes without FFmpeg.

Each job's manifest is limited to 256 entries, 512 MiB per file, and 2 GiB in total. Aliases can use up to 128 letters, digits, `.`, `_`, and `-`, and can't be only dots. Decoding decides whether a file is usable, so the response `Content-Type` is not checked.

Downloads refuse hosts that resolve to private, loopback, link-local, and other non-public addresses. The check runs on every connection, so it covers DNS rebinding and redirects. Up to 5 redirects are followed. Environment proxy settings are ignored. To download from an internal host, list it as it appears in the URL with `--allow-media-host` (repeatable; `LUMEN_SERVER_ALLOW_MEDIA_HOSTS` takes a comma-separated list).

`LUMEN_MEDIA_ROOT` is the one server-side directory a composition can reach, and only for fonts. It is not a media root for this binary. If you set it, a text node's font family is looked up in three places:

- as a path to any file inside the job directory or `LUMEN_MEDIA_ROOT`. Paths with `..`, and symlinks that lead outside the directory, are refused. The contents go only to the font parser and are never returned, but a composition can make the server read any file there, so point the variable at a directory of fonts and nothing else.
- as `fonts/<family>.ttf`, `.otf`, `.ttc`, or `.otc`, and the same with `-Regular`, with the same containment.
- by scanning `LUMEN_MEDIA_ROOT/fonts/` for `<family>.*` and `<family>-*.*` with those extensions. This scan follows symlinks without checking where they lead, so a symlink you place in that directory is trusted. Clients cannot create one: job directories only contain regular files named by alias, and an alias cannot contain `/`.

Without `LUMEN_MEDIA_ROOT`, the server's own files are not readable as fonts or media, and text can only use fonts staged in the job's manifest (`"font_family": "<alias>"`) and the bundled fonts.

`GET /renders/:id/progress` and `GET /renders/:id/socket` mirror the hosted progress shape. The WebSocket sends SDK render events like:

```json
{
  "type": "render.progress",
  "renderId": "r_123",
  "progress": 0.42
}
```

The binary exposes:

- `GET /health`
- `POST /renders`
- `GET /renders/:id`
- `GET /renders/:id/progress`
- `GET /renders/:id/socket`
- `GET /renders/:id/artifact`

Run it with:

```bash
cargo run -p lumen-server --features cli --bin lumen-server -- --bind 127.0.0.1:8080
```

When using the TypeScript SDK against the local server, set the SDK base URL to `http://127.0.0.1:8080`.

Set `--token` or `LUMEN_SERVER_TOKEN` to require `Authorization: Bearer ...` on every route except `/health`, including the WebSocket. The check runs before the request body is read. The server exits with an error if it is asked to bind a non-loopback address without a token. An empty token counts as no token.

Progress WebSocket updates are coalesced by default. Set
`--progress-min-delta` or `LUMEN_SERVER_PROGRESS_MIN_DELTA` to control the
minimum progress increase required before another non-terminal progress event is
broadcast. The value is a `0.0` to `1.0` fraction; the default is `0.02`.
Terminal updates, state changes, and stage changes are still broadcast
immediately. Set it to `0` to emit every renderer progress update.

Verbose render diagnostics are off by default. Set `--verbose-debug` or
`LUMEN_SERVER_VERBOSE_DEBUG=true` to enable detailed per-frame render progress
logs, CUDA/Vulkan device diagnostics, and frame timing output.

The renderer logs the selected adapter name, backend, device type, vendor,
device, driver, and driver details when a render starts. For software Vulkan or
non-NVIDIA validation, the same adapter-selection knobs used by `wgpu` are
available:

```bash
LUMEN_GPU_FORCE_FALLBACK_ADAPTER=1 \
WGPU_BACKEND=vulkan \
WGPU_POWER_PREF=none \
cargo run -p lumen-server --features cli,vulkan --bin lumen-server
```

On Linux CI, the SDK integration test also points Vulkan at lavapipe with
`VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json`. This is a portability
baseline, not a hardware performance target.

### Flags and environment

| Flag                              | Environment                           | Default          | Meaning                                                                                           |
| --------------------------------- | ------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------- |
| `--bind <addr>`                   | `LUMEN_SERVER_BIND`                   | `127.0.0.1:8080` | Address to listen on. A non-loopback address requires a token.                                    |
| `--token <token>`                 | `LUMEN_SERVER_TOKEN`                  | none             | Bearer token required on every route except `/health`.                                            |
| `--max-concurrent-renders <n>`    | `LUMEN_SERVER_MAX_CONCURRENT_RENDERS` | 1                | Renders that run at once.                                                                         |
| `--retained-renders <n>`          | `LUMEN_SERVER_RETAINED_RENDERS`       | 16               | Finished renders kept in memory.                                                                  |
| `--allow-media-host <host>`       | `LUMEN_SERVER_ALLOW_MEDIA_HOSTS`      | none             | Hosts allowed to resolve to non-public addresses. Repeatable, or comma-separated in the variable. |
| `--progress-min-delta <fraction>` | `LUMEN_SERVER_PROGRESS_MIN_DELTA`     | 0.02             | Minimum progress increase between non-terminal updates.                                           |
| `--verbose-debug`                 | `LUMEN_SERVER_VERBOSE_DEBUG`          | false            | Per-frame renderer diagnostics.                                                                   |
|                                   | `LUMEN_MEDIA_ROOT`                    | none             | The one directory a composition can read fonts from.                                              |
|                                   | `LUMEN_VIDEO_ENCODER`                 | platform default | Encoder name, used when the render options name none.                                             |
|                                   | `LUMEN_HARDWARE_DECODE`               |                  | `1`, `true`, `yes` or `on` turns GPU video decode on, and any other value turns it off.           |
